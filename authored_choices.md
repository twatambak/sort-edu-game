# Authored Choices

Assumptions and judgement calls made during development. Review and revise as needed.

## Current gameplay modes

- The only selectable modes are Drag and Drop and Swipe Two Directions. The swipe mode keeps its saved integer value `2`; unsupported legacy values are sanitized to Drag and Drop so existing settings do not start an unavailable mode.
- Drag targets are equal 1.2-world-unit squares at the upper sides. Items spawn in the centered neutral area below them.
- Swipe mode places group B on the left and group A on the right, matching left/right swipe scoring, with a white center divider. Group images use `ItemTypeDefinition.Background`; when an asset has no background, its category icon is used instead.
- Category images are fitted inside a fixed maximum size rather than stretched to fill the side or target. The current item type assets do not assign `_background`, so the icon fallback is intentional until dedicated group art is assigned.
- The solid square sprite is imported as a full-rect mesh so Unity's sliced `SpriteRenderer` can stretch it for panels and borders without changing its aspect ratio.
- The existing AppUI mode buttons for removed modes are hidden at runtime. The scene builder now creates only the two supported choices; other UI screens and gameplay HUD elements remain unchanged.

## App flow, menus and UI construction

- The Unity editor was open during development, so scene changes could not be made or verified directly. All screens are generated by an editor tool, `Tools > Onde Vai > Build App UI`, which creates the `AppUI` canvas and `OndeVai Systems` objects and wires every reference. It supports Undo and can be re-run (re-running replaces the generated objects).
- `GameController` gained `_beginOnStart` (default `true`, so the current scene behaves as before) and `_autoPauseOnFocusLoss` (default `false`). The builder sets them to `false`/`true` because the title screen now starts matches and a pause screen exists to resume them.
- Flow: Disclaimer (first launch only) > Title > Match > Results. Profiles, Options and Progress open from the Title screen.
- Kid-facing screens (title, pause, gameplay HUD) use icons only. Adult screens (disclaimer, profiles, options, progress) use Portuguese text.
- Options and Progress sit behind a 1.5 second hold as a light parental gate. This is not a security barrier.
- The existing pre-sliced icon sheet `Assets/Sprites/sheet_white1x.png` is mapped to semantic names in `IconLibrary.cs`. The unavailable `sheet_white2x.png` path is not imported or modified.
- Drag mode uses the diagonal arrow icon. Replace it when final art exists.
- The results screen gets a home button by duplicating `PlayAgain_Button`, hiding its label and adding a home icon. If the duplicate overlaps something, move it by hand.
- The new canvas uses sorting order 1000, above the existing results canvas (999). The pause button sits in the top-right corner and may overlap the existing HUD; I could not see the HUD layout.
- Title logo text "Onde Vai?" uses LondrinaSolid. I dropped the TMP outline because changing it in edit mode would also change the shared font material.
- `SafeAreaFitter` keeps screen content clear of notches.
- The current scene's older root-level `TitleScreen` is disabled when the generated `AppUI` is installed to prevent duplicate menus; the generated title is the active flow screen.
- The title scenario cards are limited to the requested stable IDs (`farm-jungle-animals`, `letters-numbers`, and `toys-tools`). They save a scenario choice without immediately starting the match.
- The mode selector only contains the two supported two-category modes.
- The settings and disclaimer screens are saved as `Assets/Prefabs/UI/OptionsScreen.prefab` and `Assets/Prefabs/UI/DisclaimerScreen.prefab` by the scene builder. The builder remains the source of truth for both prefab layouts and their TMP references.
- Unity updated the referenced TMP SDF font assets while rendering the generated Portuguese UI text; keep those glyph/fallback updates with the prefabs so the displayed characters remain available.

## Tutorial

- The first N items of every match (default 2, adjustable from 1 to 5, can be turned off) are guided. In drag mode a pointer drags from the item to the right storage; in swipe mode it demonstrates the matching horizontal direction.
- While the tutorial is guiding, the timer is paused and errors are not counted. They are still saved with `DuringTutorial = true` and left out of the per-category stats.
- The tutorial only applies when a `TutorialGuide` is in the scene (`RegisterTutorialPresenter`). Without one, matches behave as before.
- The pointer is a generated soft circle plus a ring because there is no hand sprite. You can assign a hand sprite to `TutorialGuide._pointer`.

## Effects and audio

- There are no particle or audio assets, so effects use pooled SpriteRenderers animated with DOTween, with circle, ring and star shapes generated at runtime. Sounds and a calm music loop are generated in code (`ProceduralAudio`). Each clip has an inspector slot on `GameAudio` for a real asset.
- Effects: sparkles on spawn, stars and a ring on a correct answer, a grey puff, small camera shake and vibration on a mistake, confetti on a win, pulsing timer in the last 5 seconds, the item grows while dragged, items fly into the box when accepted, the box flashes red when wrong, end-screen stars (optional `_stars` field, not wired by the builder), and a rising pitch on correct-answer streaks.
- Correct sorts also emit small star fireworks; errors outside the tutorial emit blue tears; the camera shake includes a subtle roll; every whole-second timer decrement emits particles; both win and loss ends trigger a confetti/firework celebration. Tutorial mistakes omit tears to keep early feedback gentle.
- Vibration only runs on Android and iOS (`Handheld.Vibrate`).
- I have not verified `AudioClip.Create` in the WebGL build. If it fails there, assign real clips.

## QOL changes to existing systems

- Dragged items are kept inside the camera view and drawn on top while held.
- Each wave of 2 or more items always has both groups, and the same prefab is not picked twice in a row.
- `ResetGame` (play again) now repeats the last configuration. Before, it always forced Classic mode.
- `DelayBetweenSpawns` is now honored by drag mode. Settings-based matches use 0, which matches the old immediate behavior.
- Storages save their resting scale before each animation, so quick repeated drops no longer make the box grow or shrink over time.
- The open/closed box sprite now counts the items inside and ignores missing sprites. One scene instance had empty sprite overrides, which could have made the box disappear.
- `ErrorCounter` no longer goes out of range and ignores tutorial mistakes. `GameTimer` unsubscribes properly.
- `FindObjectsByType<Item>` was removed from gameplay. Items are tracked by `ItemSpawner`, and storages by a static registry.
- Pausing sets `Time.timeScale` to 0. UI animations use unscaled time.

## Database

- New SQLite tables: `ChildProfileRecord` (name, age, avatar color) and `ItemAttemptRecord` (one row per sorting attempt with category, chosen category, response time and tutorial flag). `GameSessionRecord` gained `ChildProfileId`, `GameMode`, `ScenarioId` and `TutorialItemCount`. SQLite-net adds the new columns on its own; old rows are set to `ChildProfileId = 0` ("Sem cadastro").
- If the child leaves a match that had at least one attempt, the match is saved with `FinishReason = "Abandoned"`. Matches with no attempts are not saved.
- Deleting a child also deletes all of their matches and attempts. "Apagar histórico" keeps the profile.
- Ages offered are 2 to 8+. Names are trimmed, control characters are removed, and names are capped at 24 characters.
- Settings and the disclaimer acceptance are stored in PlayerPrefs (JSON), not SQLite. They are device preferences, not child data.
- I have not verified that SQLite data persists across reloads on WebGL (IndexedDB sync). This applied before my changes too.

## Scenarios

- `ItemGroup` gained values for all six scenarios in `Architecture.md`. New values were added at the end, so existing prefabs and records are unaffected.
- The builder adds six default scenarios to `GameDefinition.asset` if the list is empty. Only scenarios with prefabs in both groups appear in Options, so for now only "Brinquedos e Ferramentas" is playable.
- `Storage` has an optional `_groupIconRenderer` for showing the scenario's group icon above each box. It is not wired, because the boxes have no icon art yet.

## Defaults chosen

- Music 50%, sound effects 80%, vibration on, tutorial on with 2 items, drag mode, 30 s matches, 3 errors, 5 items on screen, 99 to win (unchanged from Classic mode).
- Option values: time 15/30/45/60/90/120 s, errors 1/2/3/5/10, items 2 to 6, tutorial items 1/2/3/5.
- Result stars: 3 at 90% or more accuracy, 2 at 60% or more, otherwise 1 (0 if nothing was sorted).

## Not done

- No asmdefs. DOTween lives in `Plugins` without an asmdef, and asmdef assemblies cannot reference the firstpass assembly.
- No unit tests. `ProgressCalculator`, `GameSettings.Sanitize` and `GameDataService.SanitizeName` are pure and ready to test once a test asmdef setup exists.

## Single item prefab and content ScriptableObjects

- Every item now comes from `Assets/Prefabs/Items/Item.prefab`. Each spawn applies the sprite, tint, scale, collider and physics (gravity, mass) from an `ItemTypeDefinition` variant.
- Variants are an inline list inside each item type asset instead of one asset per variant. They are easier to edit in bulk: drag sprites in, reorder, sort, turn variants on and off.
- Scenarios are now their own assets (`SortingScenarioDefinition`) that point to two item types. A scenario only shows in the game when both types have at least one enabled variant with a sprite.
- I wrote the data assets by hand: 12 item types (Toys and Tools moved over from the 22 old prefabs, plus 10 empty types for the other scenarios) and 6 scenarios. I generated the GUIDs and their `.meta` files myself so the references hold without opening Unity.
- I deleted the 22 `Toy_*`/`Tool_*` variant prefabs with `git rm`. Only `GameDefinition` referenced them. They can be restored from git if needed.
- Old variant names became snake_case ids (`Toy_RubberDuck` became `rubber_duck`, `Tool_Saw2` became `saw_2`). These ids go into `ItemAttemptRecord.ItemName`.
- The old variants used polygon colliders generated from the sprite. The new prefab has a `PolygonCollider2D`, rebuilt each spawn from the sprite's physics shape. If a sprite has no physics shape, the item falls back to a box. Each type, and each variant, can choose Physics Shape, Box or Circle.
- Item prefab settings now match what every old variant had: tag `StorageItem` and sorting order 5. I removed the stale `_config`/`_imageSprite` fields from the prefab.
- Items are pooled because there is only one prefab now. `Item.Despawn()` returns an item to the pool instead of destroying it. Pooled items live under a scene object named `Items`.
- Group names on the progress screen now come from the item type asset.
- The scene builder no longer fills in scenarios, since they are assets now.

## Mobile port

- Android is the main target. Its build module is installed and the Android code paths compile. The iOS module is not installed, and this is a Windows machine, so iOS is only configured (settings plus an Xcode export menu) and has not been built.
- All store and player settings live in one editable asset, `MobileBuildProfile` (`Assets/Editor/OndeVai/Mobile/`). Unity creates it on first use, so commit it. It is applied before every Android/iOS build, and you can also apply it from `Tools > Onde Vai > Mobile`. I used the API instead of editing `ProjectSettings.asset` by hand, because the open editor would overwrite manual edits.
- Defaults I chose:
  - Product name "Onde Vai?", bundle id `com.tlw.ondevai` (the company in Player Settings is TLW), version 0.1.0, build 1.
  - Portrait only, upside-down portrait allowed, because the whole layout is 1080x1920.
  - IL2CPP with Low stripping.
  - Android min SDK 25 (unchanged), target SDK automatic, ARM64 + ARMv7. ARMv7 keeps older, cheaper tablets that kids use.
  - iOS 15.0, full screen, status bar hidden.
  - **Please review the bundle id before the first store upload. It cannot change afterwards.**
- Version codes never go down. The profile value, the `BUILD_NUMBER` environment variable, and a value set by CI (`github.run_number`) all feed in, and the highest one wins.
- Keystore passwords are never stored in assets. They are read from environment variables (or CI secrets).
- `link.xml` keeps the SQLite record types and the SQLite-net assembly from being stripped by IL2CPP. SQLite-net reaches them only by reflection. This also protects the WebGL build.
- The frame rate is set to 60 on Android/iOS. They default to 30, which made dragging choppy. Web is not changed.
- The screen stays awake during a match and goes back to the system setting outside matches.
- Settings are saved when the app goes to the background, because mobile apps can be killed there without further notice.
- When the device reports low memory, unused assets are unloaded.
- Back button (Android delivers it as Escape):
  - It closes the profile form, then the open screen.
  - During a match it pauses or resumes. On the results screen it goes home.
  - It does nothing on the title and disclaimer screens, so a child can't close the app by accident.
- Only one item can be dragged at a time, so a palm or several fingers can't grab many items.
- On touch, the dragged item is raised 0.6 units above the finger so the child can see it. Change it with `DragAndDrop._touchLiftOffset` on the Item prefab.
- `CameraFitter` (added by the scene builder, or via `Tools > Onde Vai > Mobile > Add Camera Fitter To Main Camera`) widens the orthographic size on screens taller than 9:16 so the storages are never cut off. Wider screens such as tablets show more background. It checks the screen size each frame (two integer comparisons) because Unity has no resize event for world cameras.
- In `Mobile_RPAsset`, render scale went from 0.8 to 1 (0.8 blurred the sprites) and HDR was turned off (a 2D game doesn't need it, and it costs bandwidth). The Web build uses the same quality level.
- New CI workflow `build-mobile.yml` (manual run or `v*` tags): it builds a signed AAB when the keystore secrets exist and a test APK otherwise. I have not run it. Like the existing WebGL workflow, it needs the Unity license secrets.
- The app icon still uses the Unity default. Assign `AppIcon` in the profile when the art exists.

## Swipe Two Directions

- Swipe mode uses the scenario's Type A for Right and Type B for Left. The Type A panel is on the right and Type B is on the left.
- Swipe gestures use a 70-pixel minimum, require a dominant horizontal direction, and ignore vertical gestures.
- Group imagery is constrained to a consistent maximum world size so large backgrounds or sprites cannot cover the card.
- Every spawned card clears the previous answer lock; without that transition, later cards appear but reject input. Swipe input resets its pointer gesture on configuration or disable, and clears stale gestures on mismatched drag-end events.
- Accepted cards fly out in the selected direction; incorrect cards recoil and return for another try. Existing score, error, audio, haptic and particle feedback remains shared.
- The title buttons and gameplay direction hints are generated by `Tools > Onde Vai > Build App UI`; rerun it in Unity to update the existing scene canvas with the new controls.

## Profile data actions

- The settings screen's destructive actions apply only to the active child profile and require a hold confirmation.
- Clearing progress removes that child's sessions and item attempts but retains the profile. Deleting the profile removes both the profile and its history and returns the active selection to guest mode.
- The profile editor and progress screen keep their existing deletion controls; their failure paths display an error rather than implying success.
- The generated `OptionsScreen.prefab` is refreshed from `OndeVaiSceneBuilder.Screens.cs` when rebuilding App UI.
